# v1.1.0-rc.1 — 备份可靠性验收版

这是用于实际服务器验收的预发布版本。修复首版中会造成恢复内容错误、SQLite WAL 数据遗漏、跨任务误删和操作失败却返回成功的问题。

## 安装或升级

```bash
curl -fsSL https://raw.githubusercontent.com/9star-academy/bakctl/v1.1.0-rc.1/scripts/install.sh -o /tmp/bakctl-install.sh
sudo env BAKCTL_VERSION=v1.1.0-rc.1 bash /tmp/bakctl-install.sh
bakctl --version
```

预期输出：`bakctl version v1.1.0-rc.1`。脚本会先验证 SHA-256，再替换已有程序；下载或校验失败保留原安装。RC 不会替换 GitHub 的最新正式版本，因此必须指定上述版本变量。

发布文件包含 Linux amd64/arm64、macOS amd64/arm64 四个平台的单二进制，以及 `SHA256SUMS`。

## 修复内容

- 正确恢复普通文件和目录，验证完整数据后发布结果，拒绝覆盖已存在的目标。
- SQLite 必须成功完成在线备份；不会在工具缺失或失败时静默复制主库。
- 精确隔离任务的恢复选择和保留清理，同名子前缀不再误删其他任务。
- 新备份名包含高精度时间和随机后缀，避免同秒运行覆盖。
- 配置使用进程锁、最新状态事务与原子写入；备份完成不再覆盖新任务或其他任务状态。
- 配置、上传、清理和 systemd 错误均返回非零；定时运行支持等待任务锁。
- 修复 S3 SigV4 路径和查询参数编码，补齐对象列表分页。
- 新格式采用流式处理、PBKDF2-SHA256 与分块 AES-256-GCM，检测错误密码、篡改和截断。
- 安全处理符号链接，拒绝目录越界、特殊文件、递归备份和不安全归档内容。
- 更新 README、自动测试、发布校验和及安装失败保护。

## 升级注意

- **新版可以读取 v1 备份；旧版程序不能读取新版生成的备份。** 降级前保留本版本二进制和解密密码，确保新备份仍有可用的恢复工具。
- 旧备份缺少类型信息，必要时使用 `restore ... --legacy-type file|directory|raw`。
- 恢复目标必须是尚不存在的路径。`--dest` 仍可作为 `--to` 的别名。
- 不再允许同名 target/job 静默覆盖。配置变更可删除并重建任务，已有备份文件会保留。
- 若旧配置包含未生效的 `webhook_url`，请移除该字段；当前不实现通知推送。
- SQLite 需要 `sqlite3`，PostgreSQL 需要兼容版本的 `pg_dump`；定时运行需要 Linux systemd。
- 本地目标与 `TMPDIR` 必须在备份源目录以外。新格式使用临时磁盘；旧版整块密文解密仍需要相应内存。
- 普通目录备份不等于文件系统快照，持续写入的业务需单独保证一致性。

## 已完成验证

发布前本地 85 个顶层测试、race 检测、`go vet`、安装脚本检查通过，总语句覆盖率 85.8%。实际 CLI 验证加密文件逐字节一致、目录及链接恢复正确，运行中的 SQLite WAL 数据恢复后 3 行完整，`integrity_check=ok`。四个平台交叉编译通过。

S3 协议和 systemd 失败路径使用隔离测试；真实云账号、PostgreSQL 服务和 Linux timer 行为仍需实际环境验收。

## 建议验收顺序

1. 确认版本号；使用独立任务名和测试前缀完成一次 `add → run → restore`。
2. 对文件使用 `cmp`，对目录使用 `diff -r`，确认内容与结构一致。
3. SQLite 验证 `PRAGMA integrity_check;` 和关键业务行数；PostgreSQL 导入隔离测试库查询数据。
4. 测试 S3/R2 上传、恢复与保留清理，确认仅删除当前任务的旧备份。
5. 检查 `systemctl list-timers 'bakctl-*'` 与对应 service 日志。间隔 timer 首次在启用约 5 分钟后执行，之后按配置间隔触发。
